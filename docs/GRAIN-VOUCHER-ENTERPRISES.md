# v15 粮券、企业与股份经营规则

## 粮券总账

粮券使用 `src/economy/currency.js`。粮券最小单位与库存精度均为 1/3000，因此 1粮券对应3,000粮券单位，1斤小麦对应3,000库存单位。

r05 采用“先印制、后换券”。玩家在银行先印制固定数量粮券，印出的粮券直接进入镇库普通粮券余额，不消耗或冻结小麦；镇库可以把这笔粮券用于工资、采购、福利、投资或其他正常支付。居民、家庭、公司或店铺换券时，付款账户交出的实际小麦直接进入 `accounts.town.wheat`，并从镇库现有粮券余额等额转给换券方；自动换券与手动换券走同一入口。镇库粮券不足时不能换券，必须先印制。普通转账只移动粮券余额。

所有改变之后均通过 `validateCurrencyInvariant()` 核对唯一货币守恒式：

```text
issuedUnits == town balance + resident/household balance + Σ company cash + Σ shop cash
```

`reserveWheatUnits` / `reserveWheatCostVoucherUnits` 仅作为旧存档兼容字段保留并固定为 0。v15 旧档首次载入时，原独立储备和对应成本基数一次性并回镇库，此后不再参与支付预检、换券、采购、消费或改革完成条件。粮券兑回实际从镇库当前可用小麦交付，不能透支镇库库存。

## 生活自动兑换

`ensureResidentVouchersForEssential()` 只服务生活必需支付。它计算居民全部可食库存的口粮当量，保留 `basicCommerceFoodReserveDays=30` 后，才允许把多余居民小麦交给镇库换粮券。

股票、经营权不调用该路径。股份认购另要求 `shareFoodReserveDays=90` 的实际口粮储备，并从现有居民粮券中保留 `shareLivingVoucherReserveDays=30` 的生活预算。

## 上市等级和岗位

`src/systems/companies.js` 管理上市企业：

- 允许类型：mill / bakery / lumberyard / saltworks。
- 同一建筑只允许一家上市企业。
- 上市等级必须从 `ownership.townLevels` 划拨；`privateLevels` 不可收回。
- `ownership.townLevels + privateLevels + listedLevels == building.level`。
- `employment.byBuilding`、`privateByBuilding`、`listedByBuilding` 分别保存三种经营部分的岗位。
- 每上市等级固定 `sharesPerListedLevel=1000` 股，创建时全部归镇库。

升级完成的新等级只增加 `townLevels`，不会改变企业 `listedLevels/totalShares`。存在上市等级的建筑禁止拆除。

## 企业独立核算

每家公司独立保存：

- `cashVoucherUnits`
- `inventory` 与 `inventoryCostVoucherUnits`
- `payroll.arrearsVoucherUnits`
- day/year/cumulative 的 revenue、COGS、工资费用/实付、采购、实物税成本、加工损耗、利润、产量、销量、采购量、纳税量
- `retainedEarningsVoucherUnits`
- 股本、镇库持股、居民持股、股份出售记录与分红历史

原料采购付款时只把采购价计入库存成本；未售产品成本继续留在库存。产品实际售出时才确认收入和已售成本。初始资金/原料投入及后续镇库注资都是资本转移，不计营业收入。

企业工资由企业粮券账户支付。现金不足时形成企业欠薪，镇库不会自动补款。镇营和施工工资仍由镇库支付，民营继续沿用居民共同经营规则。

## 交易和公平分配

`src/systems/consumer-market.js` 为居民面包/盐建立共享需求池。镇营和所有上市卖家先共同进入卖家集合，再对当日真实需求做一次分配；不会让每个卖家各自获得一份全镇需求。

同价时使用轮换起点 + 近似均分。极小需求导致某卖家本轮未成交时，下一轮起点推进，因此固定排在后面的卖家不会永久无成交。

企业原料采购可从其他企业、居民、镇库获得。镇库建设/升级缺木材时可按当前木材价向上市企业采购；施工预览同时检查企业可售木材和镇库粮券购买力，确认时重新校验、真实成交后再一次性扣入工程。

## 企业生产税

上市企业沿用 `policy.privateProductionTaxPercent[typeId]` 的行业生产税率作为本版统一行业生产税设置。税从产出实物中扣除进入镇库，并记录对应库存成本；不额外扣粮券利润税。因此税不会既扣实物又重复扣现金。

## 股份出售与认购

上市创建时：

```text
totalShares = listedLevels * 1000
townShares = totalShares
residentShares = 0
```

首次出售只是镇库出售自己已有的股份：居民粮券→镇库，镇库股份→居民。企业现金不变。企业营运资金由独立的“追加营运资金”命令从镇库真实转账。

认购参数集中在 `src/content/rules.js`：

| 参数 | 默认 |
| --- | ---: |
| 股票口粮保护 | 90日 |
| 居民粮券生活缓冲 | 30日 |
| 经营观察期 | 30日 |
| 无历史最大认购比例 | 挂单10% |
| 估值利润年数 | 5年 |
| 利润率目标 | 20% |
| 利润率系数范围 | 0.5—1.5 |

认购预览、实际认购和界面参考业绩共用同一份日历日实际净利润估值。最近最多365个日历日都进入观察窗口，缺工、缺料、无销量和停工日不会被剔除；不足一年时按实际日历观察天数年化。无经营记录仍允许挂牌，但明确显示“暂无业绩”，只按既有无历史规则限制试探认购，不伪造历史收益。公司参考估值只使用真实净利润、投入资本与利润率：库存数量和库存成本都不直接增加估值；同利润下利润率通过统一系数影响估值。交易所、认购预览与实际认购使用同一整数每股参考值。0.1.7 之后不再用旧分红比例字段参与认购收益判断。

## 年度利润分配

每年进入新年的第1个结算日时，只结算一次上一年度：

1. 先偿付企业已有到期债务，欠薪不会因目标用工变为0而消失。
2. 按目标用工、工资和配方原料价格保留 `companyOperatingReserveDays=360` 的周转金；显式目标用工为0时新增工资/原料周转需求为0，未设置目标时才回退计划人数。
3. `可分配金额 = min(累计未分配利润, 可支付资产 - 周转金目标)`，最低为0，不再乘旧“分红比例”。
4. 未上市公司全部上交镇库；上市公司按当时镇库/居民持股比例真实转账。
5. 居民只有实际到账的年度利润分配计作投资收入；镇库所得、注资、股份出售本金和兑换不计居民收入。
6. 新年先重置家庭当日账，再记录年度分配；`lastDividendYear` 与年度结算记录防止保存恢复后重复分配。

## 默认价格

- 小麦：1粮券/斤（兑付锚）
- 面粉：1.8粮券/斤，可调
- 木材：15粮券/单位，可调
- 面包：沿用原数值2，单位改为粮券/斤，可调
- 盐：沿用原数值10，单位改为粮券/斤

以上价格由统一当前价格表提供，交易、企业采购、旧民营经营权估值、参考成本和界面展示读取同一来源。旧v7存档遇到面粉1.5/木材8时不会自动覆盖，而是提供一次可选的新版建议价格操作。
- 工资：原数值10，单位改为粮券/人日
- 失业金/公租房租金：原数值1，单位改为粮券


## 成本基数转移

企业设立时由镇库投入的初始材料会同步转移对应库存成本基数；企业以实物缴纳的生产税进入镇库时也同步转入对应成本基数。两类转移都只移动既有成本，不复制或凭空消灭成本。
