# 0.1.10-r01 存档性能与年度历史：实现、迁移与验证

## 实现范围

- 持久化容器由 v1 升为 v2，容器版本与游戏状态版本独立；目录版本保持 v1。
- v2 写入先生成一次规范 state JSON，用同一文本计算校验和并直接嵌入容器；不再再次遍历 state 生成容器正文。
- v2 读取解析容器后直接迁移已解析对象；校验复用容器内的原始 state 文本。v1 仍按旧格式重建 state 文本校验后迁移。
- IndexedDB 热保存不再为获取名称、验证旧主档和读回结果重复迁移完整 state；旧主档/备份仍做容器完整性校验，写后仍逐字节读回确认。
- 自动保存由 `autosave-coordinator` 统一串行。运行期 `session + slotId + revision` 只存在内存，不写入存档。
- 游戏状态版本 v14 → v15。旧 annualReports 转为 summaryVersion=1；年份数量不截断。

## 固定快照持久化性能

环境：Node，同一进程；固定 seed=11010 新局运行 30 日，250 个家庭，30 条账本记录。先预热，再做少量重复测量。这里仅代表 JSON/迁移计算耗时，不代表浏览器磁盘延迟或手机帧率。

| 指标 | 0.1.9 路径 | 0.1.10 路径 | 变化 |
| --- | ---: | ---: | ---: |
| 每次编码完整 state stringify 遍历 | 2 | 1 | -50% |
| 编码均值（25次） | 7.563 ms | 4.768 ms | -37.0% |
| 编码中位数 | 7.248 ms | 4.517 ms | -37.7% |
| 解码均值（15次） | 26.131 ms | 15.964 ms | -38.9% |
| 解码中位数 | 25.977 ms | 16.338 ms | -37.1% |
| 同一状态容器大小 | 792,720 B | 792,720 B | 0 B |

容器 v2 的目标是减少重复遍历，不以增加正文转义或牺牲校验换速度，因此同一快照体积没有变化。

## 定向验证

- 新 v2 容器读写、旧 v1 容器读取：通过。
- 校验损坏回退上一可读备份：通过；损坏主档未覆盖备份。
- v14 年报迁移：保留人口、劳动力、年度账、税收、家庭生活及企业年度账；移除公司/店铺日史、完整运行态和重复分红史。
- 旧年报迁移前后人口面板与账本“上一年”显示输出一致。
- 0.1.9 与 0.1.10 使用 seed=11010 各运行 30 日；除预期的 `version/schemaVersion` 14→15 外，完整实时 state 深比较一致。
- 完整新年流程：年末先封账，新年首日公司年度分配补入上一年摘要；保存恢复后不重复分配。
- 可控延迟保存：连续修订最多一个在途写；旧修订成功时新 dirty 不清除；最终落盘为最新修订。
- 可控失败保存：失败后保留上一可用进度和 dirty；同一失败修订不立即无限重试；新修订或手动强制可恢复。
- 切档/新建/删除屏障：等待在途任务；旧 slot/session 不会在操作后写入新槽或复活删除槽。
- 直接受影响的既有存档、公司年度结算与 r02 回归已重跑；未跑全量经济回归或多年经济模拟。

## 浏览器 IndexedDB 实测

尝试在容器内用 headless Chromium 做真实 IndexedDB smoke test，但本地页面在该执行环境中无法正常完成加载/脚本执行，因此未取得可信的浏览器 IndexedDB 时延或并发数据。上面的性能数字均为 Node 计算基准；并发顺序由可控延迟/失败的存储后端测试验证。
