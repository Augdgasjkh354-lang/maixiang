# 架构说明

工程使用浏览器原生 ES modules 和纯 JavaScript 模拟内核，不依赖前端框架或运行时服务。

| 目录 | 职责 |
| --- | --- |
| `src/content/` | 稳定物品 ID、岗位、建筑类型、配方、初始参数与 26 个建设地块（含南林伐木点、盐矿点）。 |
| `src/core/` | 初始状态、命令入口、固定种子随机数、无界面时钟推进、状态校验。 |
| `src/systems/` | 聚合就业、家庭年龄段与经济账户、cohort人口、农业、建设、通用生产、工资与失业金、住房租金、盐业需求、家庭需求市场、店铺、上市企业、交易、消费和满意度。 |
| `src/systems/private-industry.js`、`src/systems/operating-rights.js` | 民营经营权交易、自动用工、按需求和库存限产、民营生产原料及实物税结算。 |
| `src/economy/` | 库存增减、粮券发行/兑回/转账、原子交换、口粮当量、经营成本与逐笔账目。 |
| `src/economy/operating-plan.js` | 产业供需与用工计划的唯一来源：共享需求、短期库存目标、新企业试产、周期性计划及店铺批零价格关系。 |
| `src/economy/financial-flows.js` | 按居民/镇库分别记录年度转移、销售、消费及民营物品流；非食品保留各自单位。 |
| `src/selectors/` | 人口和岗位统计、岗位上限、生产状态、收成预测与只读仪表板。 |
| `src/selectors/operating-rights.js` | 只读经营权估值、价格上限、储备能力和岗位变化预览。 |
| `src/persistence/` | v11 状态校验、本地读写、JSON导入导出，以及 0.1.2-r04 v10→v11 一次迁移。其他旧结构不自动迁移。 |
| `src/ui/map-model.js` | 从既有 selector 结果派生只读地图展示模型；保留建筑实例 ID、地块 ID、岗位人数、施工和占用关系，不写入另一个地图状态。 |
| `src/ui/map-canvas.js`、`src/ui/terrain-art.js` | 绘制 Canvas 地形、麦浪、水纹、林缘、道路以及真实建筑和施工预览；按设备像素密度绘制。 |
| `src/ui/map.js`、`src/ui/art.js` | 生成 SVG 点击区域、建设选址标记和一致的界面/建筑图形；建筑命中层与 Canvas 使用相同世界坐标。 |
| `src/ui/map-camera.js` | 独立管理拖动、惯性、滚轮、双指缩放、镜头边界、手势捕获和拖动后的误触抑制。 |
| `src/ui/audio.js`、`src/ui/toast.js` | 用户手势后启用的合成音效、可持久化静音偏好和可清理的浮动提示。 |
| `src/ui/navigation-state.js`、`src/ui/app.js` | 选中建筑、建设预览和面板切换状态；绑定已有只读查询和业务命令。 |
| `src/ui/panel-*.js`、`src/ui/shell.js` | 建设、镇民、经营、政策、设置与建筑详情面板，以及真实粮食/人口顶部栏和底部导航。 |
| `src/styles/` | 响应式样式；主地图由 Canvas 地形与 SVG 建筑/点击层实时绘制，不依赖整张背景插画。 |
| `tests/` | 固定基准、经营规则、长期模拟、迁移和扩展内容测试。 |

`index.html` 只保留元信息、样式入口、`#app` 容器和 `src/main.js`。模拟内核不依赖 DOM、`localStorage` 或浏览器计时器。界面只从 selector 读取数据，通过命令修改就业、开工、工资、售价和政策。地图展示模型由当前 selector 结果即时派生，不进入游戏存档；建筑和工程继续使用引擎中的实例/地块 ID。镜头与 Canvas 装饰动画仅改变显示；动画由现实时间驱动，不推进模拟。隐藏页面时停止动画帧；暂停时麦浪、磨坊和面包房工作表现冻结。渲染不结算经济、不保存存档；本地保存由独立脏状态机制处理。新开与恢复的时钟均暂停，不补算离线时间。

## v16 界面与账户边界

- 高频决策数据直接显示；成本、税款、分红、交易历史和估值依据使用原生 `<details>`，默认收起。`app.js` 在同一面板重绘前保存展开项并在重绘后恢复。
- 数字编辑仍保存独立草稿；输入获得焦点时普通模拟刷新不会覆盖正在输入的值。
- 正常启动只加载当前版本存档。发现旧版本本机存档时返回 `legacy` 状态，原 JSON 不写回、不删除；用户主动开始新游戏后才写入当前结构。
- 建设、粮券和企业确认条使用 `env(safe-area-inset-*)` 适配手机安全区域。
- 本轮没有新增服务器：所谓“内部处理”仍指现有浏览器逻辑层。

整数精度、账户守恒、材料重复扣款保护、存档结构和每日结算顺序属于开发约束，不在游戏前台解释。相关细节见下文及粮券/企业文档。

### 0.1.3 聚合家庭与就业边界

- `state.cohorts` 是人口年龄结构唯一权威；总人口、未成年、劳动年龄、老人都由 cohort 汇总。家庭只保存 `ageBands.children/workers/elders`，其全镇汇总必须逐项等于 cohort。
- `state.households.byId` 是家庭库存、粮券、股份、店铺权益、生活账与岗位分配的真实来源；`accounts.residents` 与居民粮券余额只是家庭求和镜像。
- `household.jobs` 是就业唯一写入源。企业、店铺、工资、失业金、换券额度和全镇就业统计都从该表汇总；运行期不再存在 `memberIds`、个人 `jobKey`，也不维护第二套 `employment.*ByBuilding` 计数。
- 年末先由 cohort 计算死亡、增龄、成年、退休与出生，再把对应年龄段变化以稳定、受现有人数约束的整数分配规则落到家庭。劳动力减少后由同一就业释放入口收回超额岗位。
- 商业街商人和店员也是家庭岗位：商人占业主家庭 1 名劳动年龄人口；缺商人时暂停店铺并释放店员，资产与旧债权保留。
- 家庭人口为 0 时保留为非活跃资产账户，不进入普通消费、住房、就业、失业金或生活救济，但合法偿债、分红和资产追踪继续有效。
- 新形成的工资债权在形成时绑定家庭 ID；以后换岗不会改变旧债权归属。

## 每日结算顺序

1. 捕捉日初人口、建筑岗位和已建住房入住快照；按人口记入当日食盐需求，并清空仅属于“今日”的经营统计。
2. **基本口粮救济**：自动救济先于工资和可选政策。
3. **工资与欠薪**：镇营/施工工资由镇库粮券支付，上市企业工资由企业粮券账户支付；先处理历史欠薪再核定当期工资。旧工程预付抵扣余额仅抵建筑工工资。欠薪发生日计费用，之后偿还不重复计费。
4. **失业金**：使用同一份当天就业快照，只发给劳动年龄待业者；镇库不足时发可支付部分，差额不形成欠债。
5. **施工和生产**：建筑工工资已核定，按人数累加工日；材料只在建造或升级确认时重新校验并扣一次，缺木材时镇库可用粮券向上市伐木企业真实采购。随后依次处理镇营、民营和上市企业生产；三种经营归属的等级、岗位和工人互不重叠。民营从居民原料生产，上市企业从自己的库存生产并独立核算。
6. **租金**：根据日初已建住房及入住人数收取粮券；居民粮券不足时只允许将30日基本口粮保护线以上的小麦自动换券，仍不足的部分减免而非欠租。
7. **食盐购买**：先使用居民库存，只买当天需求缺口；镇营与上市卖家共享这一份需求，使用粮券公平分配成交。
8. **面包购买**：镇营与上市面包共享同一居民需求池；以粮券成交，生活自动换券仍保护30日基本口粮。
9. **口粮和食盐消费**：面包计入口粮当量并替代其他主粮；食盐独立扣除，不抵口粮。
10. **满意度和农事**：按实际吃到的面包、住房、盐保障和近30日平均农业税负渐进更新生活状态，再累加耕作投入及本日农业税率。
11. **日期、收获和年末人口**：推进日历；第274日按当年农事日平均税率和实际累计农事投入分粮，防止追溯修改和重复收成。年末先按日初年龄组结算死亡，再让幸存者增龄，最后生育、更新就业并形成年度汇总。

人口年账按 `年初劳动年龄人数 + 17 岁幸存者成年数 − 64 岁幸存者退休数 − 18 至 64 岁死亡人数 = 年末劳动年龄人数` 逐年核对。随机死亡先发生，年龄推进后发生转龄；17 岁或 64 岁当年死亡者只计入原年龄组死亡，不再计入成年或退休。达到寿命上限而移除的人口计入死亡，其中只有原年龄在 18–64 岁才属于劳动年龄死亡。

同一模拟天数在不同现实速度档下结果一致；随机数采用保存状态的 `lcg32-v1`，重载后可重放。

## 库存、工资与经营账

- 库存以整数最小单位保存（1/3000 斤），口粮当量使用 1/18000 口粮斤。输入按最近最小单位四舍五入；每种物品的换算比来自内容配置。
- 工资、失业金、租金、商品、经营权、股份和分红使用粮券账户转账；救济与农业税仍是实物。粮券先由镇库印制进入普通粮券余额；粮食换券只转移镇库已印粮券并把实物小麦收入镇库，不设独立兑付储备。
- 库存接口拒绝负数。消费、配方明确损耗才会减少全镇可食库存；不可食物品不进口粮总量。
- 配方成本按实际投入库存成本分配给各产物和损耗。面粉在作坊之间流转只继承原成本，不重新记一笔链条成本；只有面包售出时才转为已售商品成本。
- 镇营经营账继续按链条核算；上市企业另有独立收入、已售成本、工资、实物税成本、损耗和利润。原料采购先进入库存成本，未售产品不确认售价利润；资本投入不计收入。
- 欠薪在发生日计费，实际还款是账户转移，不重复计费。建造投入只计逐日施工工资；迁入旧工程时已付预付款保留并按剩余进度抵工资。
- 每座建筑保存等级及按项目记录的材料投入（物品、数量、出资账户、工程 ID、交易 ID）。拆除只归还已完成建造/升级的这些材料，不退工资、不冲销既有经营账；公共住房拆除先按剩余住房容量校验。
- 建筑等级定义在 `src/content/buildings.js`，当前上限为 5。岗位和住房容量为一级配置乘等级；每人产能不随等级变化。每级升级使用该建筑配置的相同工日与材料量。
- 账目包含稳定类型、日期、来源、去向、物品 ID、数量及原因；明细保留最近 4000 条，年报单独累积，不随年度重置。

## v14 农业税与民营经营

- 农业税逐农事日记税率基点，年度分粮按全年度实际农事日的平均税率一次结算；镇库份额向下取整至1/3000斤，余数归居民。当前税率只影响后续农事日。
- 民营生产税按建筑实例/产物累计万分之一余数；每批产物守恒拆成居民产出和镇库税品。居民投入、居民所得与税品分开记账。
- 经营权估值统一读取当前商品价、工资、税率、配方、需求、竞争库存和可用劳力。面包/盐/面粉使用实际需求机会约束；木材只按当前公共建设有预算采购缺口计算一次性参考收益，不把同一工程需求重复年化。界面另列理论满产满销人均利润用于参数校验，不承诺收益。成交必须保留居民90日基本口粮，交易收入与商品经营分列。
- 民营自动排班只从待业者安排，并先于失业金资格快照；私营工人计入总就业，不领取镇库工资/失业金。居民内部劳动成本仅用于经营评估。
- `financialFlows` 按居民/镇库和年度分类保存农业分粮、工资福利、面包/盐交易、租金、经营权交易、口粮消费、民营投入/产出/实物税。木材、食盐保留自己的物品单位，不折成粮食财富。

## 0.1.2 家庭生活结算

`src/systems/household-life.js` 是家庭生活反馈的唯一近期账入口：货币转账由 `economy/currency.js` 按交易类型落入家庭生活账；农业、救济、口粮和食盐的实物结果由对应系统记录。舒心值只读取这些实际结果与当前储备，不再从政策设置直接推导奖惩。

`src/systems/wage-claims.js` 管理按家庭归属的新欠薪债权。各雇主仍保留自己的工资负债总额，但偿付对象来自债权家庭，不从当前岗位名单重新推断。
