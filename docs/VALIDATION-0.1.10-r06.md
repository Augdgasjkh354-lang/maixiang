# 0.1.10-r06 危险 bug 定向验证

本修订仍为游戏版本 **0.1.10**、存档结构 **v15**、构建号 **0110-r06-b001**。本轮只修 3 个可实际触发的高风险一致性问题，不发布 Sites。

## 1. 公司直购统一保护家庭基本口粮

- 货币改革过渡期，家庭从镇库、商业街或公司购买商品时使用同一套基本口粮保护规则。
- 公司销售不再因为走独立销售函数而允许家庭把受保护的小麦生活储备用于结算。
- 修复复用现有 `householdConvertibleWheatUnits` 与统一支付层，没有新增第二套支付算法，也不改变支付顺序或整数精度。
- 最小复现验证：家庭只有基本口粮储备和不足额粮券时，公司直购失败，家庭小麦与公司库存都不变化。

## 2. 商业街扩容状态可正常保存

- r04 已允许单店最多 4 名商人、20 名店员，但旧存档校验仍按 1 名商人和商业街每级 8 名店员判断，合法扩店会导致保存失败。
- 校验现在从现有店铺规则与 `commercial_street.jobs` 岗位容量读取上限，不再维护过期硬编码。
- 营业店仍要求存在有效业主且至少有一名业主商人；只是允许其余合法商人共同经营。
- 最小复现验证：配置为 4 商人 / 20 店员的营业店可通过完整状态校验并完成保存。

## 3. 上市公司缩股同步收缩待售股份

- 上市公司把一个等级划回镇营时，原逻辑会按比例注销总股本和镇库持股，却保留旧的待售股数。
- 当待售股数因此大于镇库持股时，交易预览会临时取较小值掩盖问题，但完整存档校验会拒绝保存。
- 划回操作现在在同一股份变更入口同步把 `shareSale.offeredShares` 夹紧到新的镇库持股，不引入额外股份规则。
- 最小复现验证：2000 股公司划回一级后总股本、镇库持股和待售上限一致收缩到 1000 股，随后可正常保存。

## 实际测试

定向执行以下受影响范围：

- r06 三个危险 bug 最小复现；
- 商业街 4/20 容量、服务与工资；
- v15 存档保存、读取、备份和年度历史迁移；
- 公司成立、上市、缩股、回购、认购、估值与分红；
- 货币改革、混合支付与家庭基本口粮约束；
- 民营磨坊 → 面包房采购链和公共岗位；
- r05 先印制后换券、旧工资债权恢复和跨年估值修复；
- r02 公司工资绑定、构建号与 IndexedDB 故障路径。

结果：**54/54 通过**。
