# 存档与迁移说明

## 当前格式：游戏状态 v12 + IndexedDB 持久化容器

- 0.1.5 游戏状态继续使用 `version: 12`、`schemaVersion: 12`。r02 不提高游戏存档结构版本，只替换浏览器持久化容器。
- 新主存档、轮换备份和当前激活目录保存在 IndexedDB 数据库 `maixiang-save-db-v2`；新保存不再把完整 JSON 写进 `localStorage`。
- 每次新建/保存先完成状态校验与序列化，再提交 IndexedDB 事务；关键写入完成后会重新读回并校验。失败不把半成品槽设为当前存档。
- 存储恢复必须通过独立探测键的真实“写入、读回、删除、确认删除”流程。只读成功不视为恢复。

## localStorage 遗留数据迁移

启动时只识别本游戏的旧键：0.1.5-r01 多存档主槽/自动备份/目录、`maixiang-town-save-v1` 旧单存档，以及该单存档的历史备份。

1. 每个识别到的旧条目先原样写入 IndexedDB `legacy` 归档，并逐字节读回比对；校验失败即停止该迁移链，原 localStorage 不变。
2. r01 主槽与自动备份按原槽 ID 搬入 IndexedDB；更早的可读取单存档/历史备份会生成独立迁移槽。重复内容可复用同一可玩迁移槽，但每个旧键仍有独立归档记录。
3. 只有存档与目录都完成写入和读回校验后才在 IndexedDB 记录迁移完成信息。迁移过程不会自动删除 localStorage。
4. 存档管理会列出遗留条目的类型、占用与归档状态。玩家可先导出；清理必须逐项确认，而且只有已验证归档的数据允许清理。清理 localStorage 后，IndexedDB 归档仍保留。
5. 如果 localStorage 已满但仍可读取，迁移和之后的新建/保存可以完全通过 IndexedDB 继续进行；localStorage 写入探测失败只说明遗留区域仍不可写，不会把可用的 IndexedDB 判为失败。

## 故障信息

持久化错误保留 `quota / denied / serialization / validation / program` 分类与原始异常名/消息，并额外记录失败步骤、当前待写入字节数、IndexedDB 主档/轮换备份/遗留归档占用，以及 localStorage r01 主档/旧单存档/历史备份/目录占用。故障详情不包含存档正文。

## v10 → v11 一次迁移

1. 复制旧状态后读取 v10 `households.members` 与各户 `memberIds`，仅用于统计该户未成年/劳动年龄/老人数量，以及劳动年龄成员当时的岗位键。
2. `cohorts` 是迁移后的最终人口依据。若旧 member 汇总与 cohort 三年龄段不一致，按稳定家庭 ID 顺序和受当前人数约束的整数规则增减家庭年龄段，直到逐项等于 cohort；调整明细写入 `legacyMigration.v11.populationCalibration`。
3. 若某户迁移后的岗位人数超过劳动年龄人数，通过统一超额就业释放规则回收岗位，并把结果记录在 `legacyMigration.v11.employmentReleases`。
4. 保留家庭 ID、库存、粮券、股份、店铺所有权、经营权、生活账；店铺、企业、镇营/民营工资债权及其他既有负债不因迁移重分配。商业街随后通过统一岗位同步入口校验商人/店员状态。
5. 删除 `members`、`memberIds`、`nextMemberNumber`、店铺 person 引用和旧的多套就业计数表，之后生产逻辑只读写聚合模型。
6. 迁移完成后执行完整 v11 状态校验。任何提取、校准或校验失败都会抛错，原 v10 JSON 不被覆盖。迁移成功时先以 `backup-before-v11-migration-*` 保存原始 v10 文本，再写入 v11。

## 无人家庭

家庭三年龄段均为 0 时仍保留家庭记录作为非活跃资产账户。其库存、粮券、股份、店铺权益、应收欠薪及负债不自动转移或清零；该户不参与普通生活消费、住房分配、就业、失业金和生活救济。合法偿债、分红等既有资产结算仍可进入该账户。

## v15 / 0.1.10-r04 兼容修订

存档结构仍为 v15，不提高 schema 版本。旧 v15 若没有 `currency.reserveModel="town-inventory-v1"`，载入时会把旧 `reserveWheatUnits` 及对应成本基数一次性并回镇库，再把两个兼容储备字段归零并写入模型标记；再次载入不会重复释放。当前货币守恒只校验未注销发行量等于所有粮券账户余额，不再要求任何储备数量等于发行量。

r03 可能把 `managedBy="shops"` 的商业街聚合展示岗位误计入镇库工资。r04 迁移只按现有建筑定义定位并删除这些聚合 key 的镇库欠薪、债权镜像和对应改革缺券记录；真实镇营岗位的家庭债权、公司工资债务和店铺自身 liabilities 均保留。

## 历史说明

下列章节记录旧版结构演变，供维护历史测试和理解字段来源；0.1.3 正常启动不会重新执行这些旧迁移链。

## v4 补齐内容

迁移为双方账户补上缺失的新物品余额：木材和食盐默认是零，不会给镇上凭空增加资源。已用地块和工程原坐标、实例 ID 保持不动，只把新增的南林伐木点与盐矿点追加到地块目录。

旧存档获得必要的工资、经营、盐需求余数、食盐观察期、行业账、租金账和住房容量字段。已有磨坊/面包房逐实例岗位数与工资设置保留；没有的新行业不创建建筑，也不自动安排岗位。住房入住是根据当前人口、已建住房和稳定顺序只读计算，避免重复存储住户或超容量。

旧版在建工程已经预付的建筑工粮酬按原事实保留。剩余预付部分换成 `prepaidWageCreditUnits`，以后施工日抵扣建筑工工资，避免再次付同一笔钱；不向新林场、盐场、公租房追溯扣料。v1/v2 的预付款迁移公式见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## v5 建筑等级与材料投入

迁移会先备份旧版原文，再将无等级字段的既有建筑设为 1 级；已有等级、建筑 ID、地块、就业和施工状态保留。旧建筑的历史材料没有逐笔记录时，`materialInvestments` 为空，不按新版参数推算返还量。仍在施工的旧工程保留 `materialsConsumed` 中能核实的实际扣料，完工后归入该建筑的材料投入记录。拆除工程写入拆除历史，建筑岗位从当前就业表移除，但对应欠薪键、工资账目和经营历史不清除。

旧版本若已有面粉和面包但没有完整成本历史，使用公开期初成本给当前库存估值，不补造迁移前产量、销售或利润。木材、食盐的历史流水也不会伪造。

## v6 农业税与民营经营权

v5建筑等级、实例、地块、就业、工程、欠薪和材料投资记录原样保留；未持有 `ownership` 字段的旧建筑设为全镇营（镇营等级等于总等级，民营等级为0），不会自动出售。民营岗位表、税额余数、经营权售价和年度流量从零开始补齐。

v5当前年尚未收获时，已有农事日按原50%税率补入农业税日样本，未发生农事日按玩家后续选择的税率记录；若本年已收获，只保留既有库存和收获事实，不重新分粮。税负近30日平滑窗口以50%基准初始化。农业税过往没有按日历史，迁移不会推算或改写旧年收成。

年度分户收支自迁移后累计。此前的原始账目和年报仍保留，但没有可靠证据的居民/镇库细分类流量不会补造。迁移前先备份原 JSON；迁移校验失败不会覆盖存档或静默新开局。

## v7 粮券与上市企业（历史规则，r04 已取消独立储备）

v6→v7 不把既有小麦改名为粮券，也不会额外赠送任何等额货币。迁移时独立兑付储备、镇库/居民粮券余额、上市企业均从0开始，并显示一次“先发行粮券”的经营引导。原人口、年龄、地块、建筑、等级、镇营/民营归属、工程、库存、政策、农业税与生产税、经营权、随机数和历史流水保持原值。

旧 `payroll.arrearsWheatUnits` 按1:1数值迁移到 `arrearsVoucherUnits`，语义改为粮券债务；兼容字段继续镜像以便旧报表读取，不会清空旧欠薪。原粮食仍留在原物资账户，玩家需要真实把可用小麦存入兑付储备后才得到粮券。

所有旧建筑初始化 `listedLevels=0`、上市岗位为0，不会自动成立企业或出售股份。升级新增等级仍默认镇营。保存和导入时会校验：兑付储备=未注销粮券=所有粮券账户余额；建筑镇营+民营+上市等级=总等级；每家企业总股数=上市等级×1,000且镇库持股+居民持股=总股本。

`reserveWheatCostVoucherUnits` 只记录被锁定兑付小麦对应的库存成本基数，保证兑付储备进出不会扭曲后续生产成本；它不代表额外资产或货币。

## v8 统一价格与建议价格迁移

v7→v8 增加统一商品价格表，交易、企业采购、旧民营经营权估值、参考成本和界面展示共同读取它。新开局默认：小麦1粮券/斤、面粉1.8粮券/斤、面包2粮券/斤、木材15粮券/单位、盐10粮券/斤。

历史迁移函数不会把旧存档的面粉/木材价格静默改成新版默认，旧值会原样写入统一价格表。旧格式无法可靠区分“默认值”与“玩家主动设置”时仍会保留历史建议字段，但 0.1.1 正常启动不进入这条旧档迁移流程，前台也不再显示旧价格选择。

该迁移不回写历史交易、库存成本、企业利润、粮券账户、兑付储备、股份、欠薪、经营权或既有工程。公共采购需求是当前操作态，迁移后默认无采购意向，只有玩家实际选择建设/升级项目时才建立。

## v9 家庭、职业与商业街

v16 新开局使用 v9 存档结构。居民可支配资产拆分到具体家庭，新增成员职业/雇主、当日就业换券额度、店铺所有权、店铺独立现金/库存/负债与结算账。`accounts.residents` 与居民粮券汇总仅作为家庭求和镜像，不再作为独立可支出账户。

本版不实现 v8 居民公共财富向家庭账户的自动迁移。v8 及更旧存档在正常启动和导入时按不兼容存档处理，原数据不自动删除；用户明确开始新游戏后才创建 v9 状态。

## 人口年龄与劳动力账

升级不改造任何旧年龄组。新开局也保留原均摊分布：200 名未成年人分配至 0–17 岁，600 名劳动年龄人口分配至 18–64 岁，200 名老人分配至 65–84 岁。年末先按结算时年龄组抽取死亡，再将幸存者年龄增加 1 岁：17 岁幸存者进入劳动年龄，64 岁幸存者退休。劳动年龄死亡只统计年初处于 18–64 岁的死亡者，死亡者不会再重复算作成年或退休。

年度记录保存以下等式中的各项：

```text
年初劳动年龄人口 + 17岁幸存成年人数
  - 64岁幸存退休人数 - 劳动年龄人口死亡数
  = 年末劳动年龄人口
```

初始年龄带均匀分布导致前 18 年每年只有约 11 名原始未成年人长大，而劳动队列每年约有 12 人到 65 岁；再扣除劳动年龄死亡，短期劳动力可能逐年减少。之后首批出生人口达到 18 岁，补入数会随真实出生队列变化。本版只记录这一结果，不额外附加人口增长或劳动力。

## 导入、导出和恢复

“设置”可导出完整 JSON，也可导入已校验的存档。导入覆盖前先备份现有原文；结构无效时不替换。自动保存仅在模拟状态变化时触发，渲染不写存档；新开局及读档都从暂停开始。

## v10 店铺未分配利润

0.0.16 使用 v10 存档结构，为店铺加入独立的累计未分配利润字段。该字段只随经营利润、经营亏损和利润税变化，家庭追加的店铺本金不计入利润；利润实际分配后再扣减。由于旧 v9 状态没有这一独立账，本版不猜测历史本金与利润构成，v9 及更旧结构继续按不兼容存档处理，不自动迁移或删除。
