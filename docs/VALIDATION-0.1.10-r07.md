# 0.1.10-r07 危险 bug 定向验证

本修订仍为游戏版本 **0.1.10**、存档结构 **v15**、构建号 **0110-r07-b001**。本轮继续只修 3 个可实际触发的高风险一致性问题，不发布 Sites。

## 实际修复

1. **镇营旧总欠薪没有家庭债权人时永久无法偿还**
   - 旧档可能只留下 `payroll.arrearsVoucherUnits` 总额，却没有 `creditorClaims`。
   - 日薪系统过去只遍历具体债权家庭，因此即使镇库有粮券、原岗位已撤销/人数归零/人员退休，总欠薪也会永久保留。
   - 现在镇库工资链会在偿付前把未映射的历史总欠薪恢复成家庭债权：当前岗位仍存在时按岗位家庭分配；岗位已经消失时复用兼容债权分配器落到仍存在的家庭账户，再走统一支付层偿还。
   - r03 曾错误产生的商业街聚合岗位欠薪仍先按 `merchants/shop_clerks` 明确识别并清理，避免把错误债务重新分配成真实债权。

2. **已进入清算的旧店铺工资总债务没有偿还出口，并会反复吞业主补资**
   - 旧店铺总欠薪恢复债权原先只发生在正常营业的日费用计提函数。
   - 店铺一旦已经是 `liquidating`，不会再进入该函数；`fundShopLiquidation` 虽然不断从业主家庭补钱，却无法支付只有总额、没有债权人的工资债，导致清算永久卡住。
   - 现在旧店铺工资债权恢复提取为唯一辅助入口，并在所有实际支付前执行；营业、暂停和清算共用同一债权恢复规则。店铺已有足够现金时会先还债并完成清算，不再无意义追加业主资金。

3. **无人家庭仍持有上市股份时，镇库无法回购，永久锁死公司清算**
   - 家庭人口归零后仍是合法资产账户，既有股份会保留。
   - 交易所回购过去只扫描 `isActiveHousehold`，导致这部分真实股份永远不进入回购预览和执行；公司因为 `residentShares > 0` 又不能清算。
   - 现在回购扫描所有实际持股家庭账户。人口状态不再改变既有股权的回购资格；预览与实际回购继续共用相同持股表和价格规则。

## 实际测试

本轮新增最小复现 3 项，全部通过：

- 镇营岗位已消失、只有历史总欠薪：镇库余额充足时恢复家庭债权并偿清，货币转移守恒。
- 已在清算中的店铺只有历史工资总额：店铺自有现金足够时偿清并关闭，业主额外补资为 0。
- 人口归零家庭持有上市股份：回购预览可见、实际回购成功、居民股清零后公司可完成清算。

直接受影响回归共 **36/36 通过**，覆盖：

- r04 工资、商业街、换券、估值；
- r05 粮券发行、旧公司/店铺欠薪、跨年估值；
- r06 公司直购口粮保护、商业街存档容量、上市公司缩股报价；
- r07 三项最小复现；
- 公司成立/上市/认购/回购/等级变动/清算；
- 历史镇营欠薪、退休/撤岗后偿债、交易所预览。

另发现旧 `v013-aggregate-model.test.js` 中“v10→v12 成功迁移应保留原始 v10 备份”断言在 **r06 原包中同样已失败**。该项属于早期迁移容器历史测试，与本轮三处代码修改无关，因此本轮未修改旧迁移逻辑，也未计入 36 项受影响回归。
