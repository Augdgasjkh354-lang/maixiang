# v15.1 农业税与民营经营权估值

## 农业税

`policy.agricultureTaxPercent` 是当前税率，范围0%—80%、默认50%。每个有效农事日由 `systems/agriculture.js` 记录 `rateBps`（1 basis point = 0.01个百分点）。收获只读取本年度已经发生的农事日，按平均税率计算镇库份额，居民取得总收成减镇库份额的余数。冬季更改税率只影响舒心值的近期平均和下一年度耕作，不会重新结算已完成收获。

舒心值对农业税的目标修正使用最近30个游戏日的平均值：低于50%时从+10到0线性插值，高于50%时从0到−10线性插值。新存档和v5迁移用50%作为前置基准值，税率变更后逐日滚出，不会因为调一次政策立即跳满幅度。

## 经营权估值

一份经营权对应一座建筑的一个已完工等级。出售时只转换 `ownership.townLevels` 和 `ownership.privateLevels`，不变更 `level`、地块、配方效率或总岗位容量。升级增加的等级归镇营。工程期间不开放出售，带有民营份额的整栋建筑暂不能拆除。

估值只用于让居民判断是否接受本次单价，不会自动购买，也不承诺未来收益。四行业统一读取经营面板的当前商品价格、当前工资、当前生产税率、现有配方和单人产能；磨坊直接读取真实面粉市场价，不再用面包价格反推面粉价。参考收益还受可转入/待业劳动力、真实需求和竞争库存限制，未售库存不按售价确认为利润。界面另外展示“理论满产满销人均日利润”作为参数校验，并明确它不是实际收入或保证回报。

木材不再使用无限需求或零参考价。伐木场经营权只根据当前已选公共建设/升级项目的木材缺口、镇库粮券预算、居民民营木材和上市企业木材竞争库存计算一次性需求约束参考收益；没有真实采购需求时显示“暂无采购需求”，估值为有限数值0，不会出现 `Infinity`、`NaN` 或空白原因。民营与上市木材共享同一公共采购需求，采购量同时受工程缺口、卖方库存和镇库粮券限制。

售价须为正，居民还需同时满足两项：居民粮券账户足够支付；付款后所有可食粮食仍达到90天基本口粮。经营权购买不会为了投资自动兑换保护口粮。交换先整体核验，再同步转移居民粮券、镇库粮券和经营权；出售所得单列为经营权出售收入，不计作坊销售或利润。

## 自动经营和实物税

民营岗位键是建筑实例ID、岗位ID和 `private` scope 组合，自动排班只用待业者。出售后，镇营超出剩余容量的原工人优先转入刚售出的民营容量；镇营欠薪仍留在镇营工资表。民营不从居民账户转工资，也不算作镇库工资或失业金领取对象。

民营磨坊按居民面粉短缺和民营面包房目标用量生产，面包与盐按当日目标需求及居民自有库存限产，木材仍按既有生产规则形成居民自有库存；当存在公共建设采购意向时，这些居民木材可与上市企业木材一起向镇库真实出售。民营加工以具体业主家庭为经营主体：先使用其可用于生产且不侵占基本口粮储备的原料，不足部分通过统一市场与支付层真实采购；镇库库存优先供应，随后再使用其他可售库存。磨坊业主可购买小麦，面包房业主可购买面粉，不要求老板家里事先囤足生产原料。采购货款真实从业主家庭支付，卖方真实收款，生产产物归业主家庭并按既定实物税分入镇库。没有目标需求、可用劳力、市场原料或支付能力时会显示具体停产原因。

税额用每栋建筑每种产物的万分之一余数累计：`floor(产物库存单位 × 税率basis points + 上批余数 / 10,000)`，分批处理不会逐批截断逃税。总产物始终等于居民所得加镇库实物税。镇库税品不记成镇营生产；面包税品进入镇库成本簿，以物品公开开库估值登记，之后卖出只记一次商品销售回款。

## 年度收支

`src/economy/financial-flows.js` 通过统一账目入口记录农业分粮、工资与补助转移、面包/食盐购买、租金、经营权买卖、居民口粮消费及民营生产投入/产出/税品。木材、盐和面粉按各自单位记录，只有麦和口粮当量显示为粮食量。居民与镇库之间的内部转移不会作为全镇新增财富；基本口粮消费和配方损耗会减少可用食品库存。

## 扩展示例

普通民营作坊沿用现有配方结构，在 `src/content/buildings.js` 加入 `recipeId`、单级岗位和配方；出售范围在 `systems/private-industry.js` 与 `selectors/operating-rights.js` 的可售类型配置中显式登记。若是新产业，需要另外给经营估值提供输出参考价和需求规则，以及私营自动经营目标；物品库存、原子输入/输出、税额余数、劳力查询和财务账入口均复用既有接口，不应直接改写 `state.accounts`。
