# 0.1.8-r01 界面计算优化：性能与验证记录

## 改动范围

本轮只调整界面派生数据与刷新路径，不改变经济规则、日结顺序、支付预检、岗位算法、存档序列化或年度历史。

- `src/ui/dashboard-view-cache.js`：新增仅运行期存在的 Dashboard 修订缓存；不进入存档。
- `src/ui/app.js`：动画帧不再无条件构造 Dashboard；日结/状态操作主动失效，面板、选中、建设预览、暂停和速度通过视图键触发刷新；数字输入草稿留在 UI overlay，不进入经济缓存。
- `src/selectors/dashboard.js`、`dashboard-runtime.js`、`labor.js`：按当前面板计算，并在单次视图内复用建筑、地块、公司、岗位索引。
- `src/systems/household-life.js`：观察窗口与现有滚动窗口一致时，家庭近期汇总直接复用既有 totals。
- `src/economy/payment-view-state.js`、公司/店铺摘要：预览与 selector 使用只读派生状态/只读缺省值，不因打开面板懒初始化经济状态。
- `src/ui/map.js`、`map-canvas.js`：地图签名覆盖实际显示状态、等级、选择和施工进度；纯动画复用最近地图模型。

## 面板一致性

使用 r02 原始代码与 r01 优化代码，在相同固定状态下直接比较面板实际渲染 HTML：

- 新局：镇民、商业/交易所、政策、建设、地点，5/5 完全一致。
- 活跃城镇：镇民、商业/交易所、政策、建设、地点，5/5 完全一致。
- 合计 10/10 逐字一致。

此外，0.1.8 定向测试验证 selector 遍历各面板后游戏状态逐字段不变；对缺省旧字段的公司/店铺摘要也不回写状态。

## 调用次数

r02 的 `requestAnimationFrame` 路径每帧都会调用 `buildView()`。r01 的动画帧不再调用 `buildView()` 或 Dashboard cache：

- 暂停/无操作：初次渲染后，连续动画帧新增 Dashboard 构造次数为 0。
- 缓存压力测试：同一状态与选择连续请求 300 次，selector 实际执行 1 次。
- 日结完成、改变状态的操作会失效运行期修订；面板、选中建筑、建设预览、暂停/速度改变因 selection key 改变而刷新；新游戏、读取/切换存档会清空缓存。
