# 0.1.10-r05 危险 bug 定向验证

本修订仍为游戏版本 **0.1.10**、存档结构 **v15**、构建号 **0110-r05-b001**。本轮只修 3 个高风险一致性问题，不发布 Sites。

## 1. 先印制、后换券

- 银行印制固定数量粮券时，只增加镇库普通粮券余额，不消耗小麦，不建立兑付储备。
- 镇库粮券可正常用于工资、采购、福利、投资等支付；没有单独冻结的“兑换池”。
- 居民、家庭、公司、店铺交粮换券时，小麦进入镇库，粮券从镇库已有余额转给换券方；换券本身不新增 `issuedUnits`。
- 镇库粮券不足时，手动换券和自动换券都失败/受限；支付预检与实际结算读取同一镇库粮券余额。
- 货币守恒继续满足：`issuedUnits == 所有账户粮券余额之和`。

## 2. 旧档无债权人工资欠款

- 对旧档中只剩工资欠款总额、没有家庭债权人的公司/店铺/民营欠薪，先恢复为家庭债权再走现有统一支付层。
- 有对应岗位家庭时优先按岗位人数归属；岗位已经撤销、人数为 0 或人员退休后，按仍存在家庭人口分配旧债权，避免欠款永久不可偿还。
- 有钱时先偿还旧欠薪；资金不足时保留剩余债权，未偿清欠薪继续阻止公司利润分配。
- 不把兼容恢复的旧债再次记作当期工资费用。

## 3. 跨年第 365 天公司估值

- 年末重置公司年度账前，立即把旧年第 365 天日账归档到公司日历史。
- 新年 Day 0 立即挂牌、认购或查看交易所时，365 日利润窗口已经包含上一年的最后一天。
- 新年下一次正常日结不会重复归档同一个日历日。

## 实际测试

定向执行以下受影响范围：

- r05 三个危险 bug 最小复现；
- r04 工资/商业街/换券/估值回归；
- 货币改革与统一支付能力预检；
- 商业街服务交易；
- 公司成立、上市、认购、分红、365 日估值；
- 民营磨坊→面包房采购链与公共岗位；
- v15 存档读写、备份回退、v14→v15 年报迁移。

结果：**82/82 通过**。
