# 0.1.10-r03 定向验证

本修订只处理民营原料链、工资提交体验、公共建筑岗位、就业/地点界面密度和地图建筑辨识；未修改存档格式、年度历史、公司股权、支付算法或人口算法。

## 实现

- `consumer-market.js` 新增民营生产者原料采购入口，复用现有卖家发现、价格、二分支付能力与统一成交入口；只限定单一业主家庭并将镇库排在原料卖家池首位，不新增市场建筑或持久化状态。
- `private-industry.js` 在生产前按计划批次数计算可用原料。食用原料只允许使用家庭基本口粮储备以上的部分；采购量同时覆盖生产缺口与口粮储备，因此买来的小麦不会立刻又被储备保护全部锁住。
- 银行/交易所/公租房岗位分别为 8 / 8 / 20；`capacityMode: building` 表示不随建筑等级重复放大。镇营工资计提使用岗位行已经解析的实际工资，兼容旧档缺少新 roleId 工资字段的情况。
- 工资输入在 `change`/失焦时自动提交，仍保留 ✓ 与 Enter。地图为银行、交易所、政务厅、警察局、商业街、面包房使用不同绘制函数。

## 实际测试

- r03 新增定向：7/7 通过。
  - 民营磨坊从镇库购麦、保留家庭口粮并实际生产。
  - 民营面包房从镇库及上游民营业主购买面粉并生产。
  - 无原料时显示“缺面粉”等具体原因。
  - 连续 3 个完整日结中磨坊→面包房采购链持续有真实采购与生产。
  - 银行 8、交易所 8、公租房 20 岗位容量及 10/人日实际工资一致；模拟旧档缺工资键不会变成 0 薪。
  - 工资输入 change 提交规则和唯一构建号。
  - 6 类此前重复造型建筑的 Canvas 绘制命令签名互不相同。
- 直接受影响既有回归：42/42 通过，覆盖 r02 公司工资/存档迁移、经营权和民营税、0.1.7 公司交易所、移动建造确认、0.1.8 Dashboard。
- 支付/市场与公司产业链回归：18/18 通过，覆盖 0.1.9 支付能力上下文、居民市场成交、公司采购和货币阶段。

合计实际执行 67 项测试，67/67 通过。未运行全量测试或多年经济模拟。
